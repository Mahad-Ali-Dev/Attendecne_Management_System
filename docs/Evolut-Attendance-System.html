Attendance Management System

A clean, production-ready web app for employees to register, mark daily attendance, and for admins to see exactly who’s present — built on Next.js & Supabase.

1 What was built

A full-stack attendance platform with two role-based experiences — Employee and Admin — secured end-to-end by database row-level security. Employees self-register with complete verified details and a photo, then check in / out each day. Admins get live visibility of attendance across the whole team.

👤

Employee experience

Self-registration with full profile, one-tap check-in / check-out, and personal attendance history.

🛡️

Admin experience

Live “who’s present today” dashboard, team-wide stats, and a searchable employee directory.

Key features

  • Employee self-registration — full name, work email, password, CNIC (format-validated), phone, address, department, position, and profile photo upload.
  • One-tap check-in / check-out with automatic Late detection (after 09:30 PKT).
  • Personal dashboard — today’s status, profile card, and a 14-day attendance history.
  • Admin overview — live counts (Present / Late / Not-in) and a real-time table of who is in today.
  • Employee directory — profile cards with full details and per-employee 30-day attendance history.
  • Role-based access — employees see only their own data; admins see everyone (enforced by Postgres Row-Level Security).
  • Clean, responsive UI in the Evolut navy brand palette, with the company logo.

4 How to set it up

Everything is installed and the production build is verified. The only thing left is connecting your own Supabase project (about 5 minutes).

  1. Create a Supabase project

    Go to supabase.com → New project. When ready, open Project Settings → API and copy the Project URL, the anon public key, and the service_role key.

  2. Run the database schema

    In Supabase, open SQL Editor → New query, paste the entire contents of supabase/schema.sql, and click Run. This creates the tables, the photo storage bucket, and all security policies.

  3. Add your environment keys

    Copy the example file and fill in the four values:

    cp .env.local.example .env.local

NEXT_PUBLIC_SUPABASE_URL=https://YOUR-ref.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=...
SUPABASE_SERVICE_ROLE_KEY=...
NEXT_PUBLIC_BOOTSTRAP_ADMIN_EMAIL=admin@evolutecomsolutions.com

  4. Run the app

    npm install
npm run dev

    Open http://localhost:3000.

  5. First login

    Register first using the email you set in BOOTSTRAP_ADMIN_EMAIL — that account automatically becomes the Admin. Everyone else who registers is an Employee.

Make someone an admin later: run this in the Supabase SQL Editor —
update public.profiles set role = 'ADMIN' where email = 'name@evolutecomsolutions.com';

5 Deploying to production

  1. Push to Git

    Push this project to a GitHub / GitLab repository.

  2. Import to Vercel

    At vercel.com/new, import the repo. No build settings needed — it’s a standard Next.js app.

  3. Add the same 4 environment variables

    In Vercel → Project → Settings → Environment Variables, then deploy.

6 Good to know

  • Times use Pakistan Standard Time (UTC+5); the “late” cutoff (09:30) is a one-line change in src/app/dashboard/actions.ts.
  • Account creation and photo uploads run server-side with the service-role key — the secret key is never exposed to the browser.
  • Next.js is pinned to the security-patched 14.2.35 release.
  • The one thing that requires your account is creating the Supabase project — everything else is done and compiling.
